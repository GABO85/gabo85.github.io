Github secrets: an approach to this vector at scale

⏵ The problem.

Companies by mistake can leave passwords or tokens in its repositories, this become an attack vector for their CI/CD flow.


⏵ Exploring github

The (gh) client becomes helpful for this task, using it i could grab every repository owned by a company:

~ gh api "orgs/company/repos?per_page=100" --paginate --jq '.[].html_url'

The idea of this exercise was to explore a wide number of companies which allows external actors to explore its assets. Previously i saved a txt file with a list of programs which achieve the previous condition. And got each repo using this.

~ for x in `cat companies.txt`; do gh api "orgs/$x/repos?per_page=100" --paginate --jq '.[].html_url';done| tee repos.txt

I ended up with a file called repos.txt which inside had 30821 repositories. Now to explore each one (trufflehog) it's a great tool to achieve this. It covers a wide spectrum of tokens, and has the option to validete if a secret found is still active or not, this will return only valid results ready to report to the owners.

~ for z in `cat repos.txt`; do trufflehog --no-update --results=verified github --repo=$z --json --token=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx;done | tee result.json

With the flag (--results=verified) only the active tokens will be saved, also the command needs the ghp token to works, you can get one from you github account.


⏵ Results

The json file with the secrets found by trufflehog, can be explored using (jq):

* Returns every kind of token found (Algolia, AWS, data base credentials, etc...):
~ cat result.json | jq -r '.DetectorName'

* Returns (Repo, commit, file, detector name, description), based on the kind of token:
~ cat result.json | jq -r 'select(.DetectorName == "AlgoliaAdminKey")'| jq -r [.SourceMetadata.Data.Github.repository,.SourceMetadata.Data.Github.commit,.SourceMetadata.Data.Github.file,.DetectorName,.DetectorDescription]
