Github secrets: an approach to this vector at scale

⏵ The problem.

Companies by mistake can leave passwords or tokens in its repositories, this become an attack vector for their CI/CD flow.


⏵ Exploring github

The gh client becomes helpful for this task, using it i could grab every repository owned by a company:

$ gh api "orgs/company/repos?per_page=100" --paginate --jq '.[].html_url'

The idea of this exercise was to explore a wide number of companies with open bb programs. Previously i saved a txt file with a list of programs which achieve the previous condition. And got each repo using this.

$ for x in `cat companies.txt`; do gh api "orgs/$x/repos?per_page=100" --paginate --jq '.[].html_url';done| tee repos.txt

I ended up with a file called repos.txt with 30710 repositories inside. Now to explore each one trufflehog it's a great tool to achieve this. It covers a wide spectrum of tokens, and has the option to validete if a secret found is still active or not, this will return only valid results ready to report to the owners.

$ ( read -rsp "Enter your ghp_: " GITHUB_TOKEN; echo; export GITHUB_TOKEN; systemd-run --user --scope -p CPUQuota=800% -p MemoryMax=10G xargs -a repos.txt -d '\n' -P 2 -I{} sh -c 'trufflehog --no-update --results=verified --concurrency=2 github --repo="$1" --json' _ {} > results.json )

The previous command avoid your ghp_ stay in the history of linux, trufflehog will read the token from the environment variable. Also this make the process more gentle for the machine (-p CPUQuota=800% -p MemoryMax=10G), it makes available just 8 cores of the precesor and max 10gb of ram. Trufflehog will run just 2 workers for every repo. You can change this values according to your hardware.

With the flag (--results=verified) only the active tokens will be saved, also the command needs the ghp_ token to avoid rate limit, you can get one from your github account here (https://github.com/settings/credentials).

Dont forget to run the one liner inside parentheses, so your ghp_ will be discarded from your session to avoid other programs use it.


⏵ Results

The json file with the secrets found by trufflehog, can be explored using jq:

● Get every class of token found (Algolia, AWS, data base credentials, etc...):
~ cat result.json | jq -r '.DetectorName'| sort -u

● Get (Repo, commit, file, detector name, description), based on the class of token:
$ cat result.json | jq -r 'select(.DetectorName == "AlgoliaAdminKey")'| jq -r [.SourceMetadata.Data.Github.repository,
.SourceMetadata.Data.Github.commit,.SourceMetadata.Data.Github.file,.DetectorName,
.DetectorDescription]

● At this point i had a list of assets ready to explore. Using the commit and file returned, was simple to get the secret found:
$ git clone --mirror https://github.com/company/repo
$ git --git-dir=repo.git show "commit:file"| tee secret.txt
Inside secret.txt, there was the token or key found, ready to report to its rightful owner.



⏵ Lessons learned

If you are part of a security team, applying this methodology won't take too much time and will help to secure your infrastructure.
As an example the tokens found were (Alchemy, GitHubOauth2, Infura, IPinfoDB, etc)
